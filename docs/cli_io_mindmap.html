命令输入输出明细

novel init 大罗 --txt 参考小说.txt 建立项目，拆解参考小说，提炼参考书结构和世界观 ›
输入
  • --txt /path/to/参考小说.txt
  • --batch-size，默认按 20 章左右生成批次摘要
内部步骤
  • 创建 my-novels/大罗、reference、file_system
  • 复制参考小说到 reference/sample_novel.txt
  • 拆分章节到 reference/chapters
  • 提炼参考批次摘要和参考卷纲到 reference/outlines
  • 如果只有单卷，尝试智能重分卷
  • 根据参考卷纲提炼参考世界观
输出
  • reference/sample_novel.txt
  • reference/chapters/vol_xx_xxx/chapter_001.md
  • reference/chapters/_volumes.json
  • reference/outlines/vol_xx_xxx/batch_001_020.md
  • file_system/worldviews/vol_xx_worldview.md
  • file_system/reference_worldview.md
下游
  • reference/outlines 供新书大纲、分卷大纲、批次摘要使用
  • reference/chapters 供正文生成阶段参考节奏
  • reference_worldview.md 供新书世界观和映射表生成使用
novel world-import 大罗 资料路径... 导入目标世界资料，支持多个文件或目录 ›
输入
  • /path/to/封神主样本.txt
  • /path/to/封神设定资料/，目录会递归导入
  • --force 可覆盖已有导入
内部步骤
  • 识别输入路径是文件还是目录
  • 目录内的资料文件会批量收集
  • 写入导入区并生成 manifest 记录
输出
  • file_system/world_knowledge/imports/
  • file_system/world_knowledge/imports/manifest.json
下游
  • world-build 读取 imports 和 manifest，整理目标世界知识
novel world-build 大罗 将目标世界资料结构化成世界知识库 ›
输入
  • file_system/world_knowledge/imports/manifest.json
  • file_system/world_knowledge/imports/*
  • --chunk-size，无章节结构时的切片大小
  • --chapter-batch-size，按章节切片时的批次章数
  • --max-workers，兼容旧版参数；当前全栏目汇总模式通常无需设置
  • --primary，指定主资料；可填文件名、路径或资料 ID
  • --merge-only，只基于已有 worlds/<资料名>/*.md 重建 worlds/_final/ 和审计
内部步骤
  • 如果指定 --primary，以指定资料作为 primary 主资料
  • 如果未指定 --primary，选择文件体积最大的资料作为 primary 主资料
  • 其余资料作为 supplement 补充资料：不改主线，但可校正/完善力量体系、技能体系、法宝物品、角色实力背景和世界观细节
  • 优先按章节切片，每批约 20 章
  • 无法识别章节时，按字符长度切片
  • 先抽取主资料 cards，并生成 canon_index.md 作为公共知识基准
  • 补充资料提取 cards 时读取 canon_index.md，区分公共补充、样本原创和不确定内容
  • 逐片提炼 7 类资料：世界观、力量体系、关键人物、势力描述、故事主线、关键物品、技能体系
  • 每份资料内部按“2 张新 card + 上轮全栏目总结”串行汇总，一次生成 7 个栏目
  • 将全栏目汇总结果拆写为 worlds/<资料名>/世界观.md 等分栏文件
  • 按“主线守主资料、设定细节看信息质量”的规则，逐份整合补充资料到 worlds/_final/
  • 生成 audits/supplement_usage_audit.md，检查补充资料是否被过度过滤或未充分用于校正
输出
  • file_system/world_knowledge/canon_index.md
  • file_system/world_knowledge/cards/
  • file_system/world_knowledge/partials/<资料名>/_all_sections/partial_001.md
  • file_system/world_knowledge/worlds/<资料名>/世界观.md
  • file_system/world_knowledge/worlds/<资料名>/力量体系.md
  • file_system/world_knowledge/worlds/_final/世界观.md
  • file_system/world_knowledge/worlds/_final/力量体系.md
  • file_system/world_knowledge/partials/_final/_all_sections/integrated_001_xxx.md
  • file_system/world_knowledge/audits/supplement_usage_audit.md
下游
  • novel-outline 用它校验并修正新书初版设计
  • 如果在 novel-outline 后才生成，需要重新跑 novel novel-outline --force
novel novel-outline 大罗 --direction "灵感" 生成核心玩法、长线主线、舞台路线图和角色线 ›
输入
  • --direction、--direction-file 或 creative_direction.md
  • reference/outlines
  • file_system/reference_worldview.md
  • file_system/world_knowledge/worlds/_final/*.md，如果存在
内部步骤
  • 先结合参考小说玩法循环和用户灵感生成核心玩法
  • 围绕核心玩法生成独立的全书长线主线
  • 按舞台为一级类目生成全书舞台路线图
  • 基于核心玩法、长线主线和舞台路线图生成角色成长线
  • 如果存在目标世界知识库，则校正目标世界合理性；如果不存在，则自动跳过该步骤
  • 自动生成书名简介
输出
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
  • file_system/novel_name_synopsis.md
下游
  • stage-insert 可基于灵感插入新舞台并更新舞台路线图
  • mechanics-init 可基于核心玩法初始化可选机制层
  • story-arcs 读取对应卷/舞台生成故事情节单元
  • write 读取故事情节单元、章纲和舞台上下文
novel mechanics-init 大罗 --file mechanics.md 初始化可选机制层 ›
输入
  • --file 机制设定文件，优先级最高
  • --direction 或 --direction-file 机制方向
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
内部步骤
  • 判断机制层模式：none、light_state、explicit_mechanics
  • 用户提供机制设定时优先遵守；否则根据核心玩法自动判断
  • 生成规则、初始状态和展示边界
  • --none 可显式关闭机制层
输出
  • file_system/mechanics/profile.json
  • file_system/mechanics/design.md
  • file_system/mechanics/rules.json
  • file_system/mechanics/state.json
下游
  • story-arcs 读取机制层边界到 arc_context
  • chapter-outlines 可输出机制事件草案，但不自行计算数值
  • write 读取机制层状态和规则；未启用时自动忽略
novel volume-outline 大罗 生成每卷的新卷纲和新卷世界观 ›
输入
  • file_system/novel_outline.md
  • file_system/new_novel_worldview.md
  • file_system/adaptation/rewrite_map.md
  • reference/outlines/vol_xx_xxx
  • --volume 可指定单卷
  • --direction 可补充本次卷纲方向
内部步骤
  • 读取参考卷结构和新书总设计
  • 如果映射表缺失，尝试自动补生成
  • 生成单卷新大纲
  • 基于单卷大纲生成单卷世界观
  • 汇总所有分卷大纲
输出
  • file_system/new_volume_outlines/vol_01_outline.md
  • file_system/new_worldviews/vol_01_worldview.md
  • file_system/volume_outline.md
下游
  • story-arcs 用本卷大纲和本卷世界观生成故事情节单元
  • chapter-outlines 基于故事情节单元生成章纲
  • write 用本卷大纲和本卷世界观约束正文
novel story-arcs 大罗 --volume 1 生成新书故事情节单元 ›
输入
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md 中的对应卷/舞台
  • file_system/story_design/character_arcs.md
  • file_system/mechanics，如果已初始化
  • reference/outlines/vol_xx_xxx/story_arcs/arc_xxx.md
  • 旧工作区可回退读取 reference/outlines/vol_xx_xxx/batch_xxx.md
  • 本阶段不读取 reference/chapters 正文
多步流程
  • 从当前舞台的 预计章节数 推断本舞台总章数
  • 按默认约 5 章一个单元规划新书故事情节单元
  • 生成或复用当前舞台 arc_context，压缩玩法、长线、舞台、角色和机制层约束
  • 默认选取一个参考故事情节作为叙事样本，并抽象为 story_pattern
  • 基于 arc_context + story_pattern + 前序新书情节 生成新书故事情节单元
  • 写入故事情节索引，供章纲和正文阶段读取
输出
  • file_system/adaptation/arc_contexts/vol_xx_context.md
  • file_system/adaptation/story_patterns/vol_xx/arc_xxx.md
  • file_system/story_arcs/vol_xx/arc_xxx_ch001_005.md
  • file_system/story_arcs/vol_xx/arcs_index.json
语义说明
  • 日志中的参考章节范围表示“叙事模式来源”，不是新书章节与参考章节的一一对应
  • story_pattern 只保留情节功能、冲突结构、情绪节奏、爽点机制和钩子方式
  • 当前流程中一卷对应一个舞台；--stage 只是 --volume 的兼容别名，不表示卷内 stage
下游
  • file_system/story_arcs 作为章纲生成的情节蓝图
  • file_system/story_arcs 也会作为正文生成的情节背景
novel chapter-outlines 大罗 --volume 1 基于故事情节单元生成逐章章纲 ›
输入
  • file_system/story_arcs/vol_xx/arc_xxx.md
  • file_system/story_design/stage_roadmap.md 中的对应卷/舞台
  • file_system/mechanics，如果已初始化
  • 前两章章纲，如果存在
内部步骤
  • 读取已生成的故事情节单元
  • 读取机制层；启用时章纲可输出机制事件草案，但不自行计算最终数值
  • 按故事情节单元覆盖的章节范围逐章生成章纲
  • 每章读取前两章章纲，保持小范围连续性
  • 如果故事情节单元缺失，会提示先运行 story-arcs
输出
  • file_system/chapter_outlines 作为正文生成的直接蓝图
novel write 大罗 --volume 1 按照章纲生成正文 ›
输入
  • file_system/chapter_outlines/vol_xx/chapter_NNN.md
  • file_system/story_arcs/vol_xx/arc_xxx.md
  • file_system/story_design/stage_roadmap.md 中的对应卷/舞台
  • file_system/story_design/long_mainline.md
  • file_system/mechanics，如果已初始化
  • 旧工作区可回退读取 file_system/outlines/vol_xx/batch_XXX_YYY.md
  • 旧工作区可回退读取 file_system/new_volume_outlines/vol_xx_outline.md 和 file_system/new_worldviews/vol_xx_worldview.md
  • 旧工作区可选读取 file_system/adaptation/rewrite_map.md
  • reference/chapters 中按比例匹配的参考章节
  • 前两章正文，如果存在
  • core/system_prompt.md 和 core/agents.md
内部步骤
  • 确定要生成的章节范围，支持 --start 和 --max
  • 读取章纲、故事情节单元、当前舞台、长线边界和机制层约束
  • 读取对应参考章节作为节奏和写法样本
  • 调用正文生成模型
  • 写入章节正文
输出
  • file_system/chapters/vol_xx/001_第1章.md
  • file_system/chapters/vol_xx/002_第2章.md
注意点
  • 正文阶段仍会读取参考章节文本作为写法样本，需要依赖章纲和当前舞台约束避免照搬
  • 静态关键词残留扫描已停用；后续若恢复审计，应改为剧情合理性审计
novel novel-name-synopsis 大罗 生成或重生成书名简介 ›
输入
  • file_system/story_design/core_gameplay.md
  • file_system/story_design/long_mainline.md
  • file_system/story_design/stage_roadmap.md
  • file_system/story_design/character_arcs.md
  • creative_direction.md
内部步骤
  • 根据核心玩法、长线主线、舞台路线图、角色线和灵感生成书名、简介、卖点
  • novel-outline 当前会自动触发一次本能力
输出
  • file_system/novel_name_synopsis.md

关键资产传递链

参考小说链

sample_novel.txt → reference/chapters + reference/outlines → 新书结构、故事情节节奏、正文节奏。

目标世界链

可选增强链：world-import → world-build → worlds/_final/*.md → 核心玩法、长线主线、舞台路线和角色线合理性调整。没有这条链时，novel-outline 会自动降级。

舞台设计链

core_gameplay.md → long_mainline.md → stage_roadmap.md + character_arcs.md → 故事情节单元。

叙事模式链

reference story arcs + arc_context → story_pattern → new story arc。参考情节只提供结构功能和情绪节奏。

机制层链

可选链：mechanics-init → mechanics/profile.json + rules.json + state.json → 情节、章纲和正文的状态约束。

正文生成链

story arc → chapter outline → chapter text，其中正文仍会参考原书章节文本。

当前流程风险点

目标世界资料库是可选增强；如果 world-build 晚于 novel-outline 执行，目标世界资料不会自动进入既有大纲，需要重新跑 novel novel-outline --force。
novel-outline 会先生成核心玩法，再生成长线主线、舞台路线图和角色线；如果核心玩法偏了，后续舞台和情节都会被带偏。
story-arcs 和 chapter-outlines 已拆分；重跑情节单元会影响后续章纲，需要按顺序重新生成。
write 阶段仍读取参考正文，若 prompt 约束不足，旧世界细节可能重新进入正文。
